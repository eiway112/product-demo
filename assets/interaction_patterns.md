# 交互形态分类表与交互件契约

> 用途：决定「某个产品该配哪一种交互件」，以及所有交互件模板必须遵守的硬契约。
> 本文件属本体（跨产品不动），不得出现任何具体产品名或产品专有字段名。

## 一、为什么需要分类

演示件的价值不在「能点」，在「点完能自己得出结论」。所以交互件不是装饰，
而是**把产品的核心逻辑压缩成一次可自己走完的对照**。

产品的核心逻辑天然分四种形态。**按形态选件，不按产品选件**——
同一个产品换受众、换场景时形态可能变，形态一变件就换。

## 二、四类形态

| 类型 | 输入 → 输出 | 交互件 | 判定问题（有一条命中即属此类） |
|---|---|---|---|
| **计算型** | 档位 → 数值 | **档位对照器**　`calculator.html` | 产品给出的结论是**一个可算的数**吗？这些数能按档位分列、让受众自己挑一档看结果吗？ |
| **能力型** | 问题 → 样例输出 | **样例演示器**　`catalog.html` | 产品的价值在**「能把某一类事做对」**吗？受众关心的是它做出来的东西长什么样？ |
| **规格型** | 选项 → 组合与约束 | **配置器**（模板未建，规范见 §五） | 产品的本体是**一组可选规格的组合体**吗？组合之间有约束/冲突关系吗？ |
| **流程型** | 步骤 → 状态 | **流程沙盘**（模板未建，规范见 §五） | 产品的价值在**「按序把事办完」**吗？每一步有产出物或判定条件吗？ |

判定顺序：**先问有没有数**（计算型）→ 再问有没有成型输出（能力型）→
再问是不是可配组合（规格型）→ 最后问是不是有序过程（流程型）。
四问全否 → 不出交互件（见 §四）。

> **计算型的当前边界（2026-09-20 实测后写死）**：`calculator.html` 是**档位对照器**——
> 点选预设档位，面板展示该档位已实测的指标集，**页面内不做任何计算**。
> 成品里没有 `input` / `select` / `textarea` / `form`，受众无法自己填参数。
> 「受众改参数、数值随之变」是**另一种形态（实时推演）**，当前无模板，属 §五 待建项。
> 这两件事曾被同一个名字（推演器）盖住，导致配置了计算型的产品被读成「能算」。
> 判定问句里凡出现「能改参数」字样，一律视为命名回潮。

## 三、交互件硬契约（所有模板必须逐条满足）

模板与数据分离，靠下面 7 条接上。**判据脚本按这 7 条做断言，改任何一条都会让判据失效。**

| # | 契约 | 用途 |
|---|---|---|
| C1 | 数据变量名固定为 `IX_ITEMS`（数组）；区间轴固定为 `IX_AXIS`（`[lo, hi]`，可缺省） | 判据脚本按固定名取值做数据源逐项比对 |
| C2 | 主输出容器必须有 `id="ix-body"`，源码里的初始内容为 `—` | 默认态可被判定：`IX_init()` 没跑，`ix-body` 就停在 `—` |
| C3 | 必须定义 `IX_init()` 且**在脚本解析后立即调用一次** | 默认态不可省；没有默认态的交互件等于空白件 |
| C4 | item 数 ≥ 2 | 只有 1 条数据的交互件必然空转（点与不点看不出差别） |
| C5 | 模板的**可见文本**不得含中文——中文只允许出现在 CSS/JS/HTML 注释里。产品名与品牌名另由本体清洁度扫描的词表判据守 | 字段标签一律来自数据，不来自模板。这里刻意用「可见文本零中文」而不用产品名词表：词表依赖产品配置，在没有配置的干净克隆里会退化成空词表、判据静默失效；而「零中文」不依赖任何配置，到哪儿都有判别力。**已知未覆盖**：中文若写死在 `<script>` 的字符串字面量里（渲染后才进 DOM），当前判据看不见——看到模板用 JS 拼可见文案时要人工看一眼 |
| C6 | 模板脚本必须在 `IX_init()` 调用返回之后，向 `document.documentElement` 写入 `data-ix-ready` 属性；值用**拼接写法**（约定 `'IX' + 'RDY'`，运行时得 `IXRDY`） | 给行为层判据 V3 一个取证锚点：只有脚本真执行到底，DOM 上才会出现这个属性。**值必须拼接**——若在源码里写成完整字面量，V3 会**显式 FAIL**（报「注入值在原始源码中已存在」，见 `check_demo.py` 的 V3 分支），属于安全方向、**不会**悄悄放绿；代价是这条判据从此失去取证力：源码里已有这个值，它再也分不出「脚本真跑了」和「模板里恰好写了这么个字符串」 |
| C7 | 每张卡片必须是 `.ix-card` 且带 `data-ix="<序号>"`（从 0 起，与 `IX_ITEMS` 下标一一对应）；被选中项的标题容器必须有 `id="ix-title"` | 给行为层判据 V8 一个可机读的往返面：脚本据此「点第 k 张卡 → 回读 `ix-title` / `ix-body` → 与 `IX_ITEMS[k]` 逐项比对」。没有它，V8 只能证明「页面里有个交互件」，证明不了「点了以后渲染的是对的那一件」——卡片索引错位同样会「点了有变化」，光看变化看不出来 |

**模板文件格式**：一份模板 = 三段，用注释标记切分，出件器按标记抽取。

```
<!--css-->
<style> 该交互件专属样式 </style>
<!--html-->
<div> 交互件结构 </div>
<!--js-->
<script> 该交互件逻辑，末行调用 IX_init(); </script>
```

样式选择器只允许用 `.ix-` 前缀，避免与版式层互相污染。

### 模板专属占位符

除契约里的 `IX_ITEMS` / `IX_AXIS` 外，各模板可声明自己的占位符，出件器按**模板里实际出现的占位符**注入：

| 占位符 | 属于 | 含义 |
|---|---|---|
| `IX_UNIT` | 档位对照器 | 区间条右侧的单位标签 |
| `IX_STEP_LABEL` | 样例演示器 | 序号前缀（如「场景」） |

注入字典里没有的占位符会被出件器判为残留并**中止出件**，所以新增占位符时必须同步在出件器登记。

## 四、退化规则（缺数据时怎么办）

1. **归不进四类** → 不出交互件。在 `sections.html` 用
   `<section data-role="gap" data-gap-for="evidence">` 显式声明「本产品无此类证据」。
2. **有 gap 的产品，交互件数必须为 0。** 缺件时硬凑一个空件，比没有件更糟——
   受众点开发现是空的，会直接推断产品没内容。
3. **item 数 < 2** → 同按 gap 处置。1 条数据不构成对照。
4. **数值不可回指数据源** → 该 item 删除，不得沿用。

## 五、未建模板的两类：实现规范

配置器与流程沙盘**当前没有模板文件**。首次用到时按下面的规范实现，
实现后必须补负向注入（证明其默认态可被证伪），再纳入模板库。
**在模板补齐之前，需要这两类的产品一律走 §四 的 gap 处置**，不许临场手写一个专用件塞进本体。

### 配置器（规格型 → 选项 → 组合）

- 卡片 = 可选项组（每组一张卡）
- 面板 = 当前选择下的组合结果 + 约束校验结论
- `metrics` 装：当前选择项、约束校验（`tone` 用 `good`/`watch` 标可行/冲突）、组合结果描述
- 默认态 = 全部取默认选项后跑一次校验，并把结论写进 `ix-body`

### 流程沙盘（流程型 → 步骤 → 状态）

- 卡片 = 按序排列的步骤（卡片顺序即执行顺序）
- 面板 = 该步的产出物、责任角色、判定条件、耗时口径
- `metrics` 装：产出物 / 判定条件 / 口径（口径必须写清是实测值还是推算值）
- 默认态 = 停在第一步

两类都必须满足 §三 全部 7 条契约（含 C7：卡片带 `data-ix`、标题容器带 `id="ix-title"`）。

## 六、item 结构（跨四类通用）

```json
{
  "key":   "稳定标识，英文小写，仅用于定位",
  "title": "主标题（卡面大字）",
  "short": "卡面副标题（可选）",
  "body":  "说明段，一段话说清这一项是什么",
  "metrics": [
    {"label": "指标名", "value": "数值或文本"},
    {"label": "带区间的指标", "value": "52 – 56", "lo": 52, "hi": 56, "point": 54, "tone": "good"}
  ],
  "note":  "读法 / 口径注（可选，允许内联粗体标签）"
}
```

- `metrics[].lo` 与 `hi` **同时给出** → 该行渲染区间条（仅档位对照器消费，分母轴取 `IX_AXIS`）
- `metrics[].point`（可选）→ 条内实心段所到位置；不给则取 `hi`。用于区分「点估计」与「不确定区间」
- 一个 item 内只有**第一条**带 `lo`/`hi` 的指标进区间条，其余全部按普通指标行渲染
- 一条都没有 → 区间条整块隐藏，不留空条（与非计算型产品兼容）
- `tone` ∈ `good` / `watch` / 空 → 颜色语义；取值必须有口径依据，不得纯为好看
- `note` 必须写「怎么读」，不能重复 `body` 的内容

## 七、密度分档（判据阈值与依据）

五要件齐备只是骨架，下面这组阈值判的是「每个要件有没有说到位」。
阈值按**交互形态**分档，不按产品分——产品差异不该改变判据刻度。

| 判据 | 阈值 | 依据 |
|---|---|---|
| 全篇正文中文字 N5 | ≥ 700 | 新管线成品实测 914，留 23% 余量 |
| 叙事数值唯一 N5（仅计算型） | ≥ 8 | 计算型成品实测 32，取 25% 作退化警戒线 |
| 单个要件可见中文 N2 | ≥ 40 | 说清「是什么 + 为什么」约需两句完整的话；实测最低要件 100+ 字 |
| 子标题数 h3+h4 N4 | ≥ 2 | 低于此说明叙事退化成了平铺文本 |

**为什么数值密度只在计算型上要求**：能力型产品没有算子，强求数值密度只会逼出
「为凑数编数据」。这不是放水，而是承认「实证」在不同形态下载体不同——
计算型靠数值，能力型靠样例输出（由交互件 item 承载）。

**为什么要件文本下限只有 40 字**：这条判的是「不是空壳」，不是「写得够多」。
阈值定高会把正常精简的要件判死，定 40 是只拦「只剩一个标题」那种形态。

阈值全部落在 `assets/check_demo.py` 顶部的判据参数区。改任何一条，
必须同步改本节表格与代码注释——三处不一致时以代码为准，但那是缺陷不是规则。
